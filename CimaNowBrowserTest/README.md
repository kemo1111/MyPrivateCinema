# CimaNow Browser Test v1

نسخة اختبار منفصلة لسيما ناو، لا تستبدل ExampleProvider ولا تغيّر مصادره.

## التثبيت والاستخدام

1. أضف رابط `repo.json` الخاص بفرع `cimanow-test-builds` إلى مستودعات CloudStream.
2. نزّل إضافة **CimaNow Browser Test** من المستودع التجريبي.
3. اختار **CimaNow Browser Test** من قائمة المصادر.
4. افتح بطاقة **ابدأ اختبار متصفح سيما ناو** واضغط تشغيل.
5. اختار الفيلم أو الحلقة من الموقع داخل نافذة المتصفح. أكمل التحقق بنفسك، ثم اضغط تشغيل العمل من صفحة الموقع.
6. لو ظهر مرشح HLS أو MP4 تحت المتصفح، اختار مرشح العمل فقط. المرشحات ممكن تشمل إعلانات. الاختبار يفحص أول جزء من الاستجابة قبل تسليمها للمشغل.
7. زر إلغاء يقفل الاختبار. مفيش حاجة بتتغير في الإضافة الأساسية.

الترس في إعدادات الإضافة يعرض شرح الاستخدام. البحث والقوائم في النسخة دي داخل الموقع فقط. خاصية Cast غير مدعومة.

## حالة التحقق

- ده اختبار أولي، مش إعلان إن سيما ناو اشتغل على جهاز أندرويد.
- البناء واختبارات تمييز استجابة HLS/MP4 مطلوبة قبل النشر. نجاحها لا يثبت تشغيل الفيديو.
- ما اتعملش فحص بصري أو اختبار تشغيل داخل أندرويد قبل الإصدار ده. محتاج تجربة الموبايل.
- المتصفح بيحتفظ بجلسة الموقع العادية. الكود ما بيضيفش بروكسي أو خدمة توكن، ولا بيسجّل روابط الجلسة أو الكوكيز في ملفات.
- مفيش ضغط آلي على التحقق أو الإعلانات، ولا تعديل لشهادة الأمان أو هوية المتصفح.
- النوافذ المفتوحة بضغطة المستخدم بتظهر في نافذة مرئية وبزر رجوع. الروابط غير HTTPS وروابط فتح التطبيقات الخارجية غير مدعومة في الاختبار.
- مرشحات الفيديو محدودة بروابط بتنتهي مساراتها بـ`.m3u8` أو `.mp4`. الروابط بلا امتداد، وتبديل الـ DRM، والتحويلات أثناء الفحص غير مدعومة. الفحص ده مش إثبات إن الرابط للفيلم الصحيح أو إن كل مقاطع HLS هتشتغل.
- جلسة الاختبار لها مهلة ٤ دقائق ونص. إلغاء التشغيل أو إغلاق شاشة التطبيق أو تدوير الجهاز بما يدمّر الشاشة يقفل الجلسة. لا يتم حذف كوكيز المستخدم العامة.
- لو حصل حظر نهائي أو طلب متكرر للتحقق، اقفل الاختبار بدل تكرار المحاولة باستمرار.

## Code provenance

The experimental bridge, provider launcher and response-signature tests were written independently for Kareem. No provider implementation from E2iPlayer, omarC or mehdigm-stream was copied. E2iPlayer informed the high-level finding that browser-held sessions matter, not the implementation. Android and CloudStream APIs are host/platform dependencies. Existing stable provider attributions remain unchanged.
